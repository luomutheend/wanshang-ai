# DeepSeek 手表快应用 · 项目总结

- 包名：`org.coratech.deepseek.vela`
- 版本：1.0.0（versionCode 1）
- 平台：Xiaomi Vela JS 快应用（穿戴设备，`deviceTypeList: ["watch"]`）
- 设计基准宽度：`designWidth = 466`
- 开发者：落幕.
- 开源许可：AGPL-3.0-only

---

## 一、项目简介

一个运行在小米 Vela 手表 / 手环上的 DeepSeek AI 助手，支持多轮对话、联网搜索、余额查询、历史会话与 Token 用量统计。输入法基于开源 QQ 手表键盘（`merqury-vela`）改造，并按屏幕形状做了多设备适配。

## 二、功能清单

| 模块 | 说明 |
| --- | --- |
| AI 对话 | 调用 DeepSeek `/chat/completions`，支持 `deepseek-flash`（快）与 `deepseek-v4-pro`（强） |
| 联网搜索 | 调用 DeepSeek `/search`、`/fetch`，搜索结果作为上下文注入对话；失败自动降级为纯模型对话 |
| 余额查询 | 调用 `/user/balance`，展示账户可用状态、赠金 / 充值余额，支持刷新 |
| 历史会话 | 本地保存最多 20 个会话、每会话 40 条消息，可切换、清空 |
| Token 统计 | 累计输入 / 输出 / 合计 tokens、对话次数；服务端未返回 usage 时按字符估算并标注 |
| 自定义键盘 | QWERTY + 九键、中英符号切换、候选横滑、拼音小字行、震动反馈 |
| API Key 管理 | 独立存储 + 配置层双写，输入内容完整显示不遮挡 |
| 关于页 | 版本、开源说明、设备识别结果、存储诊断 |

## 五、设备适配要点

### 1. 单位规则（重要）
Vela 的 `px` **不是物理像素**，而是按 `designWidth` 等比缩放的逻辑单位。`designWidth = 466`，因此 `466px` 在任何设备上都等于整屏宽。不能用 `device.getInfo().screenWidth`（物理像素，如 RW5 = 432）直接当 CSS 宽度，否则元素只有约 93% 屏宽，右侧会出现空白并裁掉最右一列。

### 2. 设备识别
启动时 `device.getInfo()` 读取 `screenWidth / screenHeight / screenShape / deviceType / model`，在 `lib/deviceProfile.js` 归为四类：

| 族 | 设备 | 判定依据 | 键盘形态 |
| --- | --- | --- | --- |
| round | 小米手表 S4 / S5 | `screenShape === "circle"` | 480 圆屏布局 |
| rect | Redmi Watch 5 / 6 | 非圆非胶囊且宽度 > 380 | 466 视口 + 60px 键横滑 |
| band | 手环 9 Pro / 10 Pro | `deviceType === "band"` 或宽度 ≤ 380 | 同 rect，整体等比缩小 |
| pill | 手环 9 / 10 胶囊屏 | `screenShape === "pill-shaped"` | 192 弧形键盘 |

### 3. 四角圆弧安全区
- 标题栏、内容区、输入预览条都留了顶部 / 左右安全距
- 键盘底部预留 34px（设计单位）避开下方圆角
- 内容卡片宽度统一用百分比（常规 92%，圆屏 86%），避免贴到屏幕弧边

### 4. 键盘布局
- 圆屏：480 宽固定布局
- 方屏 / 手环：视口 466px（整屏宽），字母区 60px 大键、内容宽 640px，横向滑动查看全部 26 个字母；工具栏（中/英、候选、空格、删除）固定在字母区上方不随滑动
- 九键（T9）与符号页同样做了适配

## 六、关键问题与修复记录

1. **键盘右侧不显示 / 显示不全**
   根因：误把物理像素当 CSS 宽。改为固定 466px（= 设计宽）后铺满。

2. **输入预览框遮挡、文字被裁**
   改为 QQ 式单行输入条：`退出 | 输入内容 | 发送`，紧贴键盘上方，上方对话保持可见。

3. **API Key 保存后丢失**
   根因：`lib/store.js` 被分别打进每个页面 JS 包，各页面持有独立 store 实例，配置被首页默认值覆盖。
   修复：store 挂到 `global.__dsStore`，全应用共享单例；API Key 另存独立键做兜底。

4. **Token 统计一直为 0**
   同一根因（多个 store 实例）：首页写入的统计，统计页读到的是另一个空实例。
   修复：store 单例化；另外 `recordUsage` 在服务端未返回 `usage` 时按字符估算（中文约 1 字 1 token、英文 3 字符 1 token），统计页标注「其中估算 N 次」，并在回复后立即落盘。

5. **设置页按钮变窄**
   页面容器类名 `.list` 与全局样式冲突，重命名为 `.settings-list`。

## 七、存储设计

- 双写：`@system.storage`（小配置）+ `internal://files/dsdata/store.json`（大 JSON）
- 读取时按 `savedAt` 取最新一份，兼容旧根目录文件迁移
- 整包写入失败时，拆成 `deepseek_config_v1` / `deepseek_stats_v1` 两个分项兜底
- 写入串行排队（`_flushChain`），避免历史会话写入过程中丢配置
- 启动计数与存储诊断见「关于」页
